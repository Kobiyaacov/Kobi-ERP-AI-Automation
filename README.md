## על הפרויקט

**מצפן ERP היא מערכת ניהול פנימית לעסק אלקטרוניקה ישראלי דמיוני.** המערכת מרכזת לידים, לקוחות, הזמנות, מוצרים, חשבוניות ומשימות, ומשלבת אוטומציות וסוכני AI לטיפול במכירות, בשירות לקוחות ובמידע ניהולי.

הפרויקט כולל **11 תהליכי n8n, שש טבלאות Airtable, שני בוטי Telegram וממשק ניהול בעברית וב־RTL**. הוא מבוסס על מפרט הקורס, עם התאמות ותוספת של תקציר טיפול יזום למנהל.

## איך המערכת בנויה?

- **Base44:** דשבורד, מסכי ניהול, טפסים ליצירה ולעדכון וצ׳אט עם עוזר AI.
- **n8n:** תהליכי האוטומציה, סוכני AI והחיבורים לשירותים החיצוניים.
- **Airtable:** מקור הנתונים העסקיים, בטבלאות `Leads`, `Customers`, `Orders`, `Products`, `Invoice`, `Tasks`.

הפעולות מהממשק עוברות דרך פונקציית השרת `erpGateway` אל Flow 10 ב־n8n, ומשם לנתונים או לעוזר ה־AI:

<p dir="ltr" align="center"><strong>Base44 ↔ erpGateway ↔ n8n ↔ Airtable / AI</strong></p>

**שירותים נוספים:** OpenAI למודלי שפה ו־Embeddings, Gmail למיילים, Telegram לבוטים ו־Google Drive למסמכי חשבוניות. מאגרי RAG משמשים לחיפוש במדיניות העסק ובקטלוג המוצרים.

## 11 תהליכי האוטומציה

| Flow | תהליך | מה הוא עושה |
| :---: | :--- | :--- |
| 1 | קליטת לידים | מקבל פרטים דרך Webhook, בודק כפילות לפי אימייל ויוצר ליד חדש. |
| 2 | מיילי מכירות | מנסח פנייה באמצעות AI, שולח דרך Gmail ומעדכן את הליד ל־`Contacted`. |
| 3 | מאגר מדיניות | טוען מסמכי מדיניות למאגר הידע של בוט השירות. |
| 4 | מאגר מוצרים | טוען קטלוג CSV למאגר הידע לצורך חיפוש במוצרי העסק. |
| 5 | סוכן שירות לקוחות | עונה בטלגרם על שאלות בעזרת מאגרי המדיניות והמוצרים. |
| 6 | בדיקת תשובות | מאתר הודעות מלידים שפנו אליהם ומעדכן את הסטטוס ל־`Replied`. |
| 7 | אימות חשבוניות | בודק סכום ומזהה לקוח, מחשב מע״מ ומספור ומעדכן ל־`Ready` או `Invalid`. |
| 8 | הפקת מסמך | יוצר חשבונית דמו ב־HTML, מעלה ל־Drive ושומר קישור וסטטוס `Issued`. |
| 9 | סוכן המנהל | משיב לבעל העסק בטלגרם בעזרת קריאת לידים, חשבוניות, מוצרים ומשימות. |
| 10 | API לממשק | מחבר את Base44 למערכת באמצעות `read`, `create`, `update` ו־`chat`. |
| 11 | מרכז הטיפול החכם | סורק פריטים שדורשים טיפול ושולח למנהל תקציר עם סיבה והמלצת פעולה. |

**התוספת האישית, Flow 11:** מרכז לידים שהשיבו, משימות פתוחות וחשבוניות שדורשות בדיקה או הפקה. התהליך מבוסס כללים ואינו משנה רשומות בעצמו; ההחלטה והטיפול נשארים בידי המנהל.

## דוגמאות לפעולת המערכת

**מכירות:** ליד חדש נשמר ב־Airtable, נשלח אליו מייל מכירה, תגובתו מזוהה והסטטוס מתעדכן. מרכז הטיפול מציג למנהל שיש לחזור לליד.

**חשבוניות:** רשומה חדשה עוברת בדיקת נתונים וחישוב, נוצר עבורה מסמך ב־Google Drive והקישור מופיע בממשק הניהול.

**שירות לקוחות:** הלקוח שואל בבוט Telegram על החזרות או מוצרים, והסוכן נעזר במאגר הידע כדי להשיב.

במהלך הפיתוח נבדקו ידנית חיבור הממשק ל־n8n, קריאה וכתיבה ל־Airtable, יצירת ליד והזמנה מהממשק, הצ׳אט, בוטי Telegram, מסלול החשבונית ותקציר הטיפול.

## הדגמה והערות חשובות

האפליקציה החיה מוגבלת למשתמש מורשה. ניתן להציג אותה בשיתוף מסך או בהקלטה; קישור ל־GitHub אינו מעניק גישה למערכת.

זהו **פרויקט לימודי**: החשבונית נשמרת כ־HTML ולא כ־PDF, ו־`Issued` מציין הפקת מסמך ולא קבלת תשלום. הצ׳אט בתוך האפליקציה מיועד להסברים ולניסוח; בוט המנהל הוא הערוץ שקורא נתונים עסקיים. מאגר המוצרים של ה־RAG וטבלת המוצרים מנוהלים בנפרד.

פרטי ההתחברות מנוהלים ב־n8n וב־Secrets של Base44. אין לצרף למאגר סיסמאות, מפתחות API או נתונים אישיים.
